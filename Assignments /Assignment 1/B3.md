B3.1 – Statement Implementation (2 Marks)
Statement is used to execute static SQL queries. Values are directly concatenated into the SQL query.
Java Code:
import java.sql.*;

public class StatementExample {
    public static void main(String[] args) throws Exception {

        Connection con = DriverManager.getConnection(
            "jdbc:mysql://localhost:3306/transport",
            "root", "your_password"
        );

        Statement st = con.createStatement();

        String sql = "INSERT INTO bus_pass VALUES " +
                     "('P1001','192311001','Arun Kumar',12)";

        int result = st.executeUpdate(sql);

        System.out.println(result + " record inserted");

        st.close();
        con.close();
    }
}
Limitation: Directly concatenating user input can cause SQL injection and requires query construction for every different input.
B3.2 – PreparedStatement Implementation (2 Marks)
PreparedStatement uses parameterized SQL queries. It separates SQL instructions from user-provided values.
Java Code:
import java.sql.*;

public class PreparedStatementExample {
    public static void main(String[] args) throws Exception {

        Connection con = DriverManager.getConnection(
            "jdbc:mysql://localhost:3306/transport",
            "root", "your_password"
        );

        String sql = "INSERT INTO bus_pass VALUES (?, ?, ?, ?)";

        PreparedStatement ps = con.prepareStatement(sql);

        ps.setString(1, "P1002");
        ps.setString(2, "192311002");
        ps.setString(3, "Ravi Kumar");
        ps.setInt(4, 15);

        int result = ps.executeUpdate();

        System.out.println(result + " record inserted");

        ps.close();
        con.close();
    }
}
Advantages:
•	Prevents SQL injection through parameter binding.
•	Improves query readability.
•	Allows the same SQL statement to be reused with different values.
B3.3 – Batch Processing Implementation (2 Marks)
Batch processing executes multiple SQL operations together, reducing communication overhead between Java and the database.
Java Code:
import java.sql.*;

public class BatchExample {
    public static void main(String[] args) throws Exception {

        Connection con = DriverManager.getConnection(
            "jdbc:mysql://localhost:3306/transport",
            "root", "your_password"
        );

        String sql = "INSERT INTO bus_pass VALUES (?, ?, ?, ?)";

        PreparedStatement ps = con.prepareStatement(sql);

        ps.setString(1, "P1003");
        ps.setString(2, "192311003");
        ps.setString(3, "Kumar");
        ps.setInt(4, 12);
        ps.addBatch();

        ps.setString(1, "P1004");
        ps.setString(2, "192311004");
        ps.setString(3, "Priya");
        ps.setInt(4, 15);
        ps.addBatch();

        int[] results = ps.executeBatch();

        System.out.println("Batch executed successfully");
        System.out.println("Records processed: " + results.length);

        ps.close();
        con.close();
    }
}
B3.4 – Performance Comparison (2 Marks)
Compare the three approaches using the same database, table, input records and environment.
Parameter	Statement	PreparedStatement	Batch Processing
SQL handling	Dynamic SQL	Parameterized SQL	Parameterized SQL
Security	Vulnerable if input is concatenated	Protects against SQL injection	Protects against SQL injection
Query reuse	Manual query construction	Reuses prepared query	Reuses prepared query
Database communication	Individual execution	Individual execution	Groups multiple executions
Performance	Can be slower for repeated inserts	Better for repeated parameterized queries	Usually fastest for bulk inserts
Complexity Analysis:
Let n represent the number of records.
Approach	Number of executions	Time Complexity
Statement	n	O(n)
PreparedStatement	n	O(n)
Batch Processing	Approximately n/b batches	O(n)
Here, b represents the batch size. Batch processing reduces execution overhead but does not change the overall asymptotic complexity.
Conclusion: Statement is suitable for simple static SQL queries, PreparedStatement is recommended for secure parameterized queries, and batch processing is suitable for inserting large numbers of records efficiently.
